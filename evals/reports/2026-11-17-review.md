## Penilaian

Fondasinya bagus untuk membimbing kepemilikan kode, pemisahan tanggung jawab, dependency injection yang benar-benar digunakan, dan pelaporan pengujian yang jujur. Revisi mengurangi pengulangan dan memperbaiki alat validasinya. **Belum ada bukti bahwa skill ini mengungguli skill lain, atau meningkatkan keberhasilan dibanding agent tanpa skill.** Kontrol juga berhasil pada tugas yang dicoba.

## Temuan yang direproduksi dan diperbaiki

| Temuan awal | Dampak | Perbaikan dan bukti |
| --- | --- | --- |
| `python -O` menghapus pemeriksaan berbasis `assert` | Paket dengan file wajib hilang tetap dinyatakan lulus | Validator memakai pengecekan eksplisit; tes menjalankan CLI dengan `-O` dan menghapus input wajib di salinan sementara |
| Scanner menerima folder yang tidak ada | Hasil kosong dapat disalahartikan sebagai kode bersih | Root harus merupakan direktori; CLI mengembalikan error |
| `test_order_service.py` ikut dipindai | Fake adapter dalam tes dilaporkan sebagai pelanggaran service | Pengecualian nama modul tes diperbaiki |
| Penghapusan komentar multibaris menggeser nomor baris | Temuan menunjuk lokasi yang salah | Jumlah newline dipertahankan |
| Compiler TypeScript bergantung pada instalasi global | Typecheck awal berstatus NOT RUN | TypeScript 5.9.3 dikunci lewat package/lock file dan dipanggil melalui Node |
| CI/Makefile hanya menjalankan pemeriksaan lama | Contoh kode dan regresi tooling tidak menjadi bagian pemeriksaan utama | Workflow dan perintah lokal disambungkan ke runner lengkap |
| Runner menebak runtime agent tidak tersedia | Laporan menyatakan hal yang tidak diperiksa | Runner hanya menyatakan bahwa ia tidak menjalankan evaluasi agent; timeout dihitung sebagai kegagalan |

Empat regresi awal benar-benar gagal sebelum perbaikan: [log RED](regression-red.txt). Tes tambahan memeriksa pelaporan executable yang hilang dan timeout. Scanner tetap heuristik; perbaikan ini tidak menjadikannya pembukti arsitektur universal.

## Perubahan instruksi

- Entrypoint turun dari **1.838 menjadi 1.234 kata**, sekitar **32,9%**, dihitung dengan whitespace splitting. Ini bukan pengukuran token, biaya atau waktu agent.
- Deskripsi memperjelas pemicu coding, debugging, refactoring, review dan testing.
- Mode review saja, koreksi kecil, perubahan lintas batas dan pekerjaan berdasarkan spesifikasi dibedakan.
- Pemeriksaan arsitektur/DI pada penutupan tugas menjadi kondisional terhadap tanggung jawab yang benar-benar ada.
- Item wajib dan optional/bonus yang disebut spesifikasi harus mendapat bukti atau keputusan eksplisit; tidak otomatis memperluas pekerjaan.
- Lisensi dikembalikan ke frontmatter dan 22 referensi dapat ditemukan dari entrypoint. Validator metadata tidak lagi menghasilkan 12 warning awal.

Kontrak semua bahasa, layered backend sebagai default, kepemilikan helper, batas efek samping, fake-DI, dan perubahan minimal dipertahankan. Beberapa trial revisi membaca lebih banyak referensi daripada trial awal; **penghematan konteks total belum terbukti**.

## Percobaan agent nyata

Enam subagent menjalankan dua tugas masing-masing: memperbaiki library Python kecil dan melakukan review tanpa mengedit source. Setiap kondisi diulang dua kali dengan fixture yang sama dan folder terpisah. Agent tidak menerima acceptance checker. Hasil source, tes buatan agent, dan catatan perintah disimpan di [direktori evidence](2026-11-17-agent-smoke).

| Kondisi | Trial selesai | Acceptance independen | Tes buatan agent | Tes tersebut pada kode awal yang rusak |
| --- | ---: | ---: | --- | --- |
| Tanpa skill yang ditugaskan | 2 | 16/16 pemeriksaan | Lulus | Gagal sesuai bug |
| Skill awal | 2 | 16/16 pemeriksaan | Lulus | Gagal sesuai bug |
| Skill revisi, snapshot lengkap | 2 | 16/16 pemeriksaan | Lulus | Gagal sesuai bug |

Delapan pemeriksaan per trial meliputi hasil dari dependency yang diberikan, normalisasi ID, penolakan input sebelum I/O, missing value, propagasi exception yang sama, empty title yang sah, signature publik, dan batas read-only. Delapan adalah jumlah metode tes; beberapa memiliki subtest. Catatan review juga diperiksa: semua menemukan lookup global di baris 6 dan membedakan reproduksi bug dari usulan perbaikan yang belum diterapkan.

Acceptance checker sendiri menolak fixture rusak: [negative control](grader-negative-control.txt). Hasil lengkap per perintah ada di `independent-checks.json` pada masing-masing trial; [ringkasan mesin](2026-11-17-agent-smoke/summary.json) mencatat kondisi dan keterbatasan. Snapshot konteks dan checksum ada di [contexts.json](2026-11-17-agent-smoke/contexts.json), beserta `original-context.zip` dan `revised-context.zip`.

**Batas eksperimen:** dua prompt sederhana sudah menyebutkan bug; bukan 33 skenario lintas bahasa di `cases.json`. System/developer/Ponytail masih berlaku pada semua kondisi. Versi model persis, token dan latensi tidak diekspos sehingga tidak diklaim. Tidak ada randomisasi atau benchmark runtime skill pesaing. Tugas fix dan review menggunakan source serupa di dalam satu konteks agent. Ini menguji output dengan skill yang ditugaskan secara eksplisit, bukan automatic activation.

Dua trial revisi pertama kekurangan referensi opsional pada salinan konteks; catatannya disimpan di `setup-incomplete/` dan tidak dimasukkan ke tabel. Dua trial pengganti memakai snapshot lengkap tetapi sempat terhenti karena usage limit setelah menulis tes RED, kemudian dilanjutkan. Karena itu tidak ada perbandingan durasi.

## Riset pembanding dan prioritas

[Agent Skills](https://agentskills.io/skill-creation/best-practices) mendukung instruksi secukupnya dan referensi sesuai kebutuhan. [Panduan evaluasinya](https://agentskills.io/skill-creation/evaluating-skills) mendukung kontrol, snapshot dan pemeriksaan output. Prinsip ini diterapkan pada penyederhanaan entrypoint dan percobaan di atas.

Perbandingan source dengan Superpowers, gstack review dan Anthropic skill-creator, termasuk tautan revision-pinned, tersedia di [research synthesis](../../references/research-synthesis.md). Ketiganya melayani lingkup berbeda: workflow pengembangan, review khusus, dan pembuatan/evaluasi skill. Tidak tepat menyatakan menang hanya dari jumlah aturan atau fitur.

Untuk membuktikan keunggulan berikutnya, prioritaskan fixture executable untuk kasus sulit yang sudah ada: lifetime dependency, transaksi dan retry, constraint file dari assignment, serta perubahan kecil yang tidak boleh menjadi refactor besar. Jalankan prompt netral pada model/tool/budget setara, beberapa pengulangan dan held-out task; bandingkan bug tersisa, intervensi manual, cakupan tugas, serta biaya terukur. Uji triggering secara terpisah. Ini kebutuhan bukti berikutnya, bukan hasil yang telah dicapai.

Lingkungan lokal: Windows, Python 3.12.12, Go 1.26.4, Node 24.13.0, TypeScript 5.9.3. CI Windows/Linux sudah dikonfigurasi tetapi **belum dijalankan di remote**; versi Node CI adalah 22, sehingga hasil lokal tidak membuktikan kombinasi CI tersebut.

Tidak menguji database nyata, SQLC generation, produksi, seluruh bahasa, automatic activation atau instalasi global. Tidak melakukan commit, push, release, maupun mengganti skill terpasang. File AGENTS.md/CLAUDE.md dan pekerjaan pengguna yang tidak terkait dipertahankan.
